# 广告设计公司客户对接平台 1.0 需求分析报告

版本：1.0  
日期：2026-07-20  
阶段定位：项目骨架搭建、核心页面成型、常见基础功能可用  
依据文档：`项目.docx`、`docs/需求分析报告.md`

## 1. 版本目标

1.0 版本是项目第一次开发交付版本，目标不是完成全部复杂业务，而是搭建可继续迭代的系统骨架，并完成主要页面、角色入口、基础数据流和部分常见功能。

1.0 需要让项目具备以下能力：

1. 仓库结构清晰，前后端项目可以独立启动。
2. 访客、客户、设计师三类使用入口明确。
3. 首页、作品集、案例详情、登录注册、沟通工作台、项目列表、项目详情等核心页面具备可演示界面。
4. 登录、角色区分、基础列表查询、详情查看、基础聊天消息、阶段按钮展示等常见功能可用。
5. 后续 2.0 可以在该骨架上继续补充文件上传、阶段确认细节、实时通讯、项目归档等小功能。

## 2. 用户角色

### 2.1 访客

访客无需登录即可访问对外展示页面。

1.0 范围内，访客需要能够：

- 查看首页。
- 浏览作品集列表。
- 使用基础筛选和关键词搜索。
- 查看案例详情。
- 点击咨询入口进入登录或注册页面。

### 2.2 客户

客户是外部委托方，通过客户前台进入项目沟通和项目进度页面。

1.0 范围内，客户需要能够：

- 使用演示客户账号登录。
- 查看自己的项目列表。
- 进入项目沟通工作台。
- 查看聊天记录并发送文字消息。
- 查看业务阶段按钮及当前状态。
- 查看项目详情、进度条和阶段时间线。

### 2.3 设计师

设计师是广告设计公司内部用户，通过设计师端管理客户项目和沟通。

1.0 范围内，设计师需要能够：

- 使用演示设计师账号登录。
- 查看负责的项目列表。
- 进入项目沟通工作台。
- 查看客户消息并发送文字回复。
- 查看业务阶段按钮及当前状态。
- 查看项目详情和基础进度信息。

## 3. 1.0 功能范围

### 3.1 首页

功能说明：

- 展示平台名称、广告设计公司业务定位和主要服务入口。
- 展示精选作品或作品集入口。
- 提供“免费咨询”“联系我们”入口。

验收标准：

- 打开客户前台首页时页面结构完整。
- 首页能清晰引导用户进入作品集、案例详情或登录注册。
- 页面在桌面端显示正常，无明显错位和遮挡。

### 3.2 作品集列表

功能说明：

- 以网格或瀑布流形式展示作品案例。
- 每个案例展示封面、标题、行业、风格、服务类型。
- 支持行业、风格、服务类型筛选。
- 支持关键词搜索。

1.0 实现要求：

- 可使用后端种子数据或前端静态演示数据。
- 筛选和搜索需要具备基础可用效果。
- 暂不要求复杂排序、推荐算法和高级搜索。

验收标准：

- 作品集列表可以正常展示多条案例。
- 点击筛选条件后列表结果发生变化。
- 输入关键词后能筛选标题或说明中包含关键词的案例。

### 3.3 案例详情

功能说明：

- 展示案例标题、行业、风格、服务类型、设计说明。
- 展示一组案例图片或占位图。
- 提供返回作品集和发起咨询入口。

验收标准：

- 从作品集列表点击案例可进入详情页。
- 详情页能展示案例基础信息。
- 返回和咨询入口可点击。

### 3.4 登录与角色区分

功能说明：

- 支持客户和设计师登录。
- 登录后根据角色进入对应页面。
- 支持基础注册页面，但 1.0 可只完成页面与基础表单，不要求完整短信验证码能力。

1.0 演示账号：

| 角色 | 账号 | 密码 | 登录后入口 |
| --- | --- | --- | --- |
| 客户 | customer@example.com | 123456 | 客户工作台 |
| 设计师 | designer@example.com | 123456 | 设计师工作台 |

验收标准：

- 客户账号登录后进入客户端项目或工作台页面。
- 设计师账号登录后进入设计师端项目或工作台页面。
- 未登录访问受保护页面时跳转登录页。
- 登录状态刷新页面后不应立即丢失。

### 3.5 沟通工作台

功能说明：

工作台采用类微信布局：

- 左侧：项目/会话列表。
- 中间：聊天消息区域。
- 顶部：业务阶段按钮区。
- 底部：消息输入区。

1.0 实现范围：

- 展示项目/会话列表。
- 展示聊天消息。
- 支持发送文字消息。
- 展示系统消息。
- 展示 7 个业务阶段按钮。
- 展示按钮状态，但不要求完成完整双方确认闭环。

业务阶段按钮：

1. 需求引导。
2. 签订合同预付款。
3. 资料调研报告。
4. 草图风格敲定。
5. 审稿定稿。
6. 交付尾款。
7. 售后复购。

1.0 按钮状态：

- 待发起。
- 等待确认。
- 已达成。
- 已驳回。

验收标准：

- 客户和设计师均可进入工作台页面。
- 工作台布局清楚，能区分会话列表、聊天区和阶段按钮区。
- 输入文字并发送后，消息显示在聊天区。
- 切换会话时，聊天区内容随会话变化。
- 阶段按钮能展示不同状态样式。

### 3.6 项目列表

功能说明：

- 客户查看自己的项目。
- 设计师查看负责的项目。
- 项目列表展示项目名称、客户、设计师、当前阶段、项目状态、最近更新时间。

验收标准：

- 登录后可看到项目列表。
- 点击项目可进入项目详情或沟通工作台。
- 客户端和设计师端展示字段可以不同，但核心信息完整。

### 3.7 项目详情

功能说明：

- 展示项目基本信息。
- 展示当前进度条。
- 展示阶段时间线。
- 展示基础里程碑视图。
- 展示文件归档区域入口或占位模块。

1.0 实现范围：

- 项目详情页面结构完成。
- 进度条和时间线可根据演示数据展示。
- 文件归档可先做模块占位，实际上传下载放到 2.0。

验收标准：

- 从项目列表可进入项目详情。
- 项目详情显示项目名称、当前阶段、客户、设计师。
- 进度条和时间线展示正常。

## 4. 1.0 不包含范围

以下内容不作为 1.0 必须完成项，进入 2.0 或 3.0：

- WebSocket 实时通讯。
- 图片、文件、表情消息的完整上传和预览。
- 双方确认阶段流转的完整后端状态机。
- 阶段文件归档和下载。
- 消息已读/未读。
- 合同 PDF 在线生成。
- 电子签。
- 数据看板。
- 移动端深度适配或小程序。
- Elasticsearch 搜索。
- 生产级权限审计和操作日志。

## 5. 数据需求

1.0 至少需要以下演示数据：

- 客户账号 1 个。
- 设计师账号 1 个。
- 作品案例不少于 6 条。
- 项目不少于 2 个。
- 每个项目至少包含 1 个会话。
- 每个会话至少包含客户消息、设计师消息、系统消息。
- 每个项目包含 7 个业务阶段的状态数据。

## 6. 页面清单

客户前台/客户端：

- 首页。
- 作品集列表页。
- 案例详情页。
- 登录页。
- 注册页。
- 客户项目列表页。
- 客户沟通工作台。
- 客户项目详情页。

设计师端：

- 设计师登录页。
- 设计师项目列表页。
- 设计师沟通工作台。
- 设计师项目详情页。

通用页面：

- 404 页面。
- 无权限或未登录跳转处理。

## 7. 权限要求

1.0 版本权限以角色区分为主：

- 访客只能访问首页、作品集、案例详情、登录注册。
- 客户只能访问客户端页面和自己的演示项目数据。
- 设计师只能访问设计师端页面和自己负责的演示项目数据。
- 受保护页面必须校验登录状态。

## 8. 验收场景

1. 访客打开首页，进入作品集列表。
2. 访客使用筛选和搜索查看案例。
3. 访客进入案例详情页。
4. 访客点击咨询入口进入登录或注册页面。
5. 客户使用演示账号登录。
6. 客户查看项目列表并进入沟通工作台。
7. 客户发送一条文字消息。
8. 客户查看项目详情、进度条和时间线。
9. 设计师使用演示账号登录。
10. 设计师进入同一项目沟通工作台并发送回复。
11. 设计师查看阶段按钮状态和项目详情。
12. 刷新页面后登录态和基础数据展示正常。
